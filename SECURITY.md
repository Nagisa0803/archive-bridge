# Security and privacy

Do not submit credentials, real account ZIPs, private photo links, device restore archives or raw network captures in public issues. A useful safe report includes only the release version, OS/CPU, error code and synthetic reproduction.

The collector is intended for a single user on a trusted computer. It binds to loopback and uses per-launch tokens plus origin/host validation. It does not store credentials, disable TLS verification, install certificates or send account data to the viewer website. Process memory is not a secure vault and forensic erasure is not guaranteed.

Before reporting a vulnerability publicly, contact the maintainer to arrange a private report without including secrets. See the source for the supported version boundary and exact method allowlist.
